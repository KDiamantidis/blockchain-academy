Μία από τις πιο κοινές αιτίες ευπαθειών web εφαρμογών είναι η λανθασμένη διαχείριση δεδομένων εισόδου (input) και εξόδου (output). Αν μια εφαρμογή δεν ελέγχει σωστά αυτά που στέλνεις, μπορείς να εκμεταλλευτείς αυτή την αδυναμία.

## 5.1 Τι είναι το input validation;

Το **input validation** είναι ο έλεγχος ότι τα δεδομένα που εισάγει ένας χρήστης είναι αναμενόμενα, ασφαλή και στη σωστή μορφή.

> **Αναλογία:** Φαντάσου ένα ATM που σου ζητάει το PIN σου. Αν δεν ελέγχει ότι εισάγεις μόνο αριθμούς, ένας κακόβουλος χρήστης θα μπορούσε να εισάγει ειδικούς χαρακτήρες για να παραπλανήσει το σύστημα.

### Τι πρέπει να ελέγχει η εφαρμογή;

- **Τύπος δεδομένων:** Είναι αριθμός, κείμενο, ημερομηνία;
- **Μήκος:** Δεν επιτρέπουμε κείμενο 10.000 χαρακτήρων σε ένα username field.
- **Μορφή:** Είναι valid email address, valid URL κ.λπ.;
- **Εύρος τιμών:** Μια ηλικία δεν μπορεί να είναι αρνητική.
- **Χαρακτήρες:** Αποτρέπει ειδικούς χαρακτήρες που μπορούν να χρησιμοποιηθούν για επιθέσεις.

## 5.2 Server-side και client-side validation

Αυτή είναι μία κρίσιμη διάκριση:

- **Client-side validation:** Γίνεται στον browser με JavaScript. Βοηθάει στην εμπειρία χρήστη (UX) αλλά **δεν παρέχει ασφάλεια** και μπορεί να παρακαμφθεί εύκολα.
- **Server-side validation:** Γίνεται στον server. **Πάντα απαραίτητη.** Ο χρήστης δεν μπορεί να την παρακάμψει.

> **Λανθασμένο παράδειγμα:** Η εφαρμογή ελέγχει την ηλικία μόνο με JavaScript. Ένας hacker μπορεί να στείλει απευθείας HTTP request με αρνητική ηλικία, παρακάμπτοντας τον έλεγχο.
>
> **Σωστό παράδειγμα:** Ο server ελέγχει πάντα την τιμή πριν την επεξεργαστεί, ανεξάρτητα από αυτό που στέλνει ο client.

## 5.3 Output encoding

Ακόμα κι αν κάποιος καταφέρει να εισάγει κακόβουλα δεδομένα, το **output encoding** εμποδίζει αυτά τα δεδομένα να εκτελεστούν ως κώδικας.

> **Encoding:** Η μετατροπή ειδικών χαρακτήρων σε ασφαλείς αναπαραστάσεις. Π.χ. ο χαρακτήρας `<` γίνεται `&lt;` σε HTML.

Παράδειγμα: αν ένας χρήστης εισάγει:

```html
<script>alert('hacked')</script>
```

...και η εφαρμογή εμφανίζει αυτό το κείμενο χωρίς encoding, τότε ο browser θα εκτελέσει το script! Αυτό είναι **Cross-Site Scripting (XSS)** (θα το δούμε αναλυτικά στο Κεφάλαιο 7).

Με σωστό output encoding, ο χαρακτήρας `<` μετατρέπεται σε `&lt;` και ο browser τον εμφανίζει σαν κείμενο αντί να τον εκτελεί.

## 5.4 Λάθη που κάνουν οι developers

Ορισμένα κοινά λάθη στη διαχείριση input/output:

### 1. Trust user input

Οι developers υποθέτουν ότι οι χρήστες θα εισάγουν μόνο έγκυρα δεδομένα. Λάθος! Πάντα υπόθεσε ότι το input είναι δυνητικά κακόβουλο.

### 2. Incomplete validation

Ελέγχουν μερικά πεδία αλλά όχι όλα. Οι επιτιθέμενοι θα βρουν το πεδίο που δεν ελέγχεται.

### 3. Blacklisting και whitelisting

- **Blacklisting (κακή πρακτική):** Αποτρέπεις συγκεκριμένους χαρακτήρες/τιμές. Πρόβλημα: οι επιτιθέμενοι βρίσκουν τρόπους να τις παρακάμψουν.
- **Whitelisting (καλή πρακτική):** Επιτρέπεις μόνο συγκεκριμένους χαρακτήρες/τιμές. Οτιδήποτε άλλο απορρίπτεται.

### 4. Error messages

Λεπτομερή μηνύματα σφάλματος (π.χ. «SQL Error: table users does not exist») αποκαλύπτουν πληροφορίες για την εσωτερική δομή της εφαρμογής. Πάντα εμφάνιζε γενικά μηνύματα σφάλματος στον χρήστη και κράτα τα λεπτομερή σφάλματα σε εσωτερικά logs.

## 5.5 Παράδειγμα: λανθασμένη και σωστή επικύρωση

Ας δούμε ένα πρακτικό παράδειγμα search box.

Λανθασμένη υλοποίηση:

```php
// Χρησιμοποιεί απευθείας το input σε SQL query
$query = "SELECT * FROM products WHERE name = '" . $_GET['search'] . "'";
```

Σωστή υλοποίηση:

```php
// Χρησιμοποιεί prepared statements για ασφάλεια
$stmt = $pdo->prepare('SELECT * FROM products WHERE name = ?');
$stmt->execute([$_GET['search']]);
```

## Σύνοψη

- Το input validation ελέγχει ότι τα δεδομένα εισόδου είναι ασφαλή και αναμενόμενα.
- Η επικύρωση client-side βοηθάει το UX αλλά δεν είναι ασφαλής. Απαιτείται server-side validation.
- Το output encoding εμποδίζει κακόβουλα δεδομένα να εκτελεστούν ως κώδικας.
- Χρησιμοποίησε whitelisting αντί για blacklisting.
- Μην εμπιστεύεσαι ποτέ άκριτα το user input.
