Για να κατανοήσεις πώς να προστατεύσεις ή να εκμεταλλευτείς κάτι, πρέπει πρώτα να καταλάβεις πώς λειτουργεί. Σε αυτό το κεφάλαιο θα μάθεις τα θεμέλια του World Wide Web, πώς ο browser σου "μιλάει" με έναν server και τι συμβαίνει κάθε φορά που επισκέπτεσαι μία σελίδα.

## 2.1 Η αρχιτεκτονική client-server

Το Internet λειτουργεί με ένα απλό μοντέλο: υπάρχουν **Clients** (πελάτες) και **Servers** (εξυπηρετητές).

- **Client:** Είναι η συσκευή σου (υπολογιστής, κινητό) και το πρόγραμμα που χρησιμοποιείς (browser). Κάνει αιτήματα (requests) για πληροφορίες.
- **Server:** Είναι ο υπολογιστής που φιλοξενεί το site ή την web εφαρμογή. Λαμβάνει αιτήματα και στέλνει πίσω απαντήσεις (responses).

> **Αναλογία:** Φαντάσου ότι πας σε ένα εστιατόριο. Εσύ είσαι ο client, ο σερβιτόρος μεταφέρει το αίτημά σου, και η κουζίνα (server) ετοιμάζει και στέλνει το φαγητό.

## 2.2 Τι είναι το URL

Το **URL** (Uniform Resource Locator) είναι η διεύθυνση ενός πόρου στον ιστό: μιας σελίδας, μιας εικόνας, ενός αρχείου. Χωρίς αυτό, ο browser δεν θα ήξερε ποιον server να ρωτήσει ούτε τι να ζητήσει από αυτόν.

### Τα μέρη ενός URL

```text
https://www.example.com:443/shop/shoes.html?color=red&size=42#reviews
```

| Μέρος | Στο παράδειγμα | Τι κάνει |
| --- | --- | --- |
| Scheme | `https` | Το πρωτόκολλο που θα χρησιμοποιηθεί |
| Host | `www.example.com` | Ο server που θα ρωτηθεί (μέσω DNS βρίσκεται η IP του) |
| Port | `443` | Η «πόρτα» του server. Αν λείπει, μπαίνει η default: 80 για http, 443 για https |
| Path | `/shop/shoes.html` | Ποιον πόρο ζητάμε μέσα στον server |
| Query string | `?color=red&size=42` | Επιπλέον παράμετροι, σε ζεύγη όνομα=τιμή χωρισμένα με `&` |
| Fragment | `#reviews` | Θέση μέσα στη σελίδα |

Το host μπορεί να σπάσει και αυτό σε μέρη: στο `www.example.com`, το `com` είναι το TLD, το `example.com` είναι το domain και το `www` είναι subdomain. Διαβάζεται από δεξιά προς αριστερά.

### Τι γίνεται με κάθε μέρος

- Το scheme, το host και το port καθορίζουν σε ποιον server θα συνδεθεί ο browser και με ποιο πρωτόκολλο.
- Το path και το query string πηγαίνουν στον server μέσα στο request. Για το URL παραπάνω, η πρώτη γραμμή του request είναι `GET /shop/shoes.html?color=red&size=42 HTTP/1.1`.
- Το fragment **δεν στέλνεται ποτέ** στον server. Το διαβάζει μόνο ο browser, για να κάνει scroll σε σημείο της σελίδας ή για να το χρησιμοποιήσει η JavaScript.

### URL encoding

Στα URL επιτρέπονται μόνο ορισμένοι χαρακτήρες. Οι υπόλοιποι γράφονται ως `%` και τον κωδικό τους σε δεκαεξαδική μορφή:

- το κενό γίνεται `%20`
- το `&` μέσα σε τιμή γίνεται `%26`
- το `<` γίνεται `%3C`

Αυτό χρειάζεται γιατί χαρακτήρες όπως `?`, `&`, `#`, `/` έχουν ειδική σημασία μέσα στο URL, άρα δεν μπορούν να χρησιμοποιηθούν ως απλό κείμενο.

### Σύνδεση με την ασφάλεια

- **Οι παράμετροι του URL είναι input του χρήστη.** Ο χρήστης μπορεί να τις αλλάξει ελεύθερα. Από εκεί προκύπτουν το SQL Injection, το Reflected XSS και το IDOR (`?id=1234`) που θα δούμε στα επόμενα κεφάλαια.
- **Το URL ως όρισμα.** Όταν μια παράμετρος περιέχει άλλο URL (`?url=...`), ο server μπορεί να εξαναγκαστεί να το επισκεφθεί. Αυτό είναι το SSRF.
- **Παραπλανητικά domains.** Στο `bank.com.evil.com` το πραγματικό domain είναι το `evil.com`, γιατί το host διαβάζεται από δεξιά. Αυτή είναι μια συνηθισμένη τεχνική phishing.
- **Ευαίσθητα δεδομένα στο URL.** Passwords και session IDs δεν μπαίνουν ποτέ σε URL, γιατί αποθηκεύονται στο ιστορικό του browser, στα logs των servers και στο header `Referer`.
- **Origin.** Το scheme, το host και το port μαζί είναι το origin που χρησιμοποιεί η Same-Origin Policy (Κεφάλαιο 3).

## 2.3 Τι είναι το HTTP;

Το **HTTP** (HyperText Transfer Protocol) είναι το «γλωσσικό πρωτόκολλο» που χρησιμοποιούν ο client και ο server για να επικοινωνούν. Ορίζει πώς πρέπει να μοιάζουν τα αιτήματα και οι απαντήσεις.

> **Πρωτόκολλο:** Ένα σύνολο κανόνων που καθορίζει πώς γίνεται η επικοινωνία, όπως ακριβώς η ανθρώπινη γλώσσα έχει γραμματική και σύνταξη.

Κάθε φορά που γράφεις μια διεύθυνση στον browser (π.χ. `http://example.com`), ο browser στέλνει ένα HTTP αίτημα στον server. Ο server απαντάει με το περιεχόμενο της σελίδας.

## 2.4 Τι είναι το HTTPS;

Το **HTTPS** (HTTP Secure) είναι η κρυπτογραφημένη έκδοση του HTTP. Χρησιμοποιεί πρωτόκολλο TLS/SSL για να κρυπτογραφήσει την επικοινωνία μεταξύ browser και server.

> **Κρυπτογράφηση:** Η μετατροπή δεδομένων σε μορφή που δεν μπορεί να διαβαστεί από τρίτους χωρίς το κατάλληλο «κλειδί».

Πώς ξέρεις αν μια σύνδεση είναι HTTPS; Δες τη γραμμή διεύθυνσης του browser σου: θα δεις ένα λουκέτο και η διεύθυνση θα ξεκινά με `https://`. Χωρίς HTTPS, κάποιος που «παρακολουθεί» το δίκτυο μπορεί να δει τα δεδομένα σου (κωδικούς, πιστωτικές κάρτες κ.λπ.) σε απλό κείμενο.

## 2.5 HTTP requests, τα αιτήματα

Ένα HTTP request (αίτημα) αποτελείται από συγκεκριμένα μέρη. Ας το δούμε αναλυτικά.

### Μέθοδοι HTTP (HTTP Methods)

Υπάρχουν διαφορετικοί τύποι αιτημάτων ανάλογα με τι θέλουμε να κάνουμε:

- **GET:** Ζητάει δεδομένα από τον server. Π.χ. «Δώσε μου αυτή την ιστοσελίδα». Δεν αλλάζει τίποτα στον server.
- **POST:** Στέλνει δεδομένα στον server για επεξεργασία. Π.χ. «Εδώ είναι τα στοιχεία σύνδεσής μου, κάνε με login».
- **PUT:** Αντικαθιστά δεδομένα στον server.
- **DELETE:** Ζητάει τη διαγραφή δεδομένων.
- **PATCH:** Ενημερώνει μέρος δεδομένων.

### Παράδειγμα HTTP request

Όταν επισκέπτεσαι το `https://www.example.com/login`, ο browser σου στέλνει κάτι σαν:

```http
GET /login HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0 (Windows NT 10.0)
Accept: text/html
Cookie: session_id=abc123
```

Ας αναλύσουμε κάθε γραμμή:

- **`GET /login HTTP/1.1`:** Ο τύπος αιτήματος (GET), η σελίδα που ζητάμε (`/login`), και η έκδοση του πρωτοκόλλου.
- **`Host`:** Ποιον server απευθυνόμαστε.
- **`User-Agent`:** Ποιο πρόγραμμα κάνει το αίτημα (browser + λειτουργικό σύστημα).
- **`Accept`:** Τι είδους απάντηση θέλουμε.
- **`Cookie`:** Αποθηκευμένα δεδομένα σύνδεσης (θα το δούμε αναλυτικά αργότερα).

## 2.6 HTTP responses, οι απαντήσεις

Ο server απαντάει με ένα HTTP response (απάντηση) που επίσης έχει δομημένη μορφή:

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
Set-Cookie: session_id=xyz789; HttpOnly

<html>...περιεχόμενο σελίδας...</html>
```

### Κωδικοί κατάστασης HTTP (Status Codes)

Ο server χρησιμοποιεί αριθμητικούς κωδικούς για να σου πει τι συνέβη:

- **2xx, επιτυχία:** 200 OK (όλα καλά), 201 Created (δημιουργήθηκε νέο στοιχείο).
- **3xx, ανακατεύθυνση:** 301 Moved Permanently, 302 Found (προσωρινή ανακατεύθυνση).
- **4xx, σφάλμα client:** 400 Bad Request, 401 Unauthorized (δεν έχεις πιστοποιηθεί), 403 Forbidden (δεν έχεις άδεια), 404 Not Found.
- **5xx, σφάλμα server:** 500 Internal Server Error, 503 Service Unavailable.

Από προοπτική ασφάλειας, οι κωδικοί 4xx και 5xx είναι πολύ σημαντικοί καθώς συχνά αποκαλύπτουν πληροφορίες για τη δομή μιας εφαρμογής.

## 2.7 Τι είναι τα cookies

### Το πρόβλημα που λύνουν

Το HTTP είναι **stateless**: ο server επεξεργάζεται κάθε request ανεξάρτητα και δεν κρατάει μνήμη των προηγούμενων. Αν κάνεις login και μετά ζητήσεις τη σελίδα `/profile`, για τον server το δεύτερο request είναι από άγνωστο άτομο.

Χρειάζεται λοιπόν ένας τρόπος να «δένονται» τα requests ενός χρήστη μεταξύ τους. Τα cookies είναι αυτός ο τρόπος.

### Τι είναι ένα cookie

Ένα cookie είναι ένα μικρό κομμάτι δεδομένων που ο server δίνει στον browser. Ο browser το αποθηκεύει και το στέλνει πίσω στον ίδιο server σε κάθε επόμενο request.

> **Αναλογία:** στην είσοδο ενός πάρκου σου δίνουν βραχιολάκι, και σε κάθε έλξη το δείχνεις αντί να ξαναπληρώσεις.

### Πώς δουλεύει βήμα-βήμα

1. Ο browser ζητάει μια σελίδα, χωρίς cookie ακόμα:

   ```http
   GET / HTTP/1.1
   Host: shop.example.com
   ```

2. Ο server απαντάει και ζητάει να αποθηκευτεί ένα cookie, με το header `Set-Cookie`:

   ```http
   HTTP/1.1 200 OK
   Set-Cookie: session_id=abc123; Path=/; HttpOnly; Secure
   ```

3. Ο browser το αποθηκεύει (στη συσκευή σου). Σε κάθε επόμενο request προς τον ίδιο server το στέλνει αυτόματα, με το header `Cookie`:

   ```http
   GET /profile HTTP/1.1
   Host: shop.example.com
   Cookie: session_id=abc123
   ```

4. Ο server βλέπει `abc123`, βρίσκει ποιος χρήστης αντιστοιχεί σε αυτό και απαντάει ανάλογα.

Δύο σημεία που μετράνε για την ασφάλεια:

- Ο server αποφασίζει τι cookie θα μπει, ο browser αποφασίζει πότε θα το στείλει.
- Η αποστολή είναι **αυτόματη**. Ο browser δεν ρωτάει τον χρήστη ούτε τη σελίδα.

### Από τι αποτελείται ένα cookie

Ένα cookie έχει attributes που ορίζουν πώς θα συμπεριφέρεται:

| Attribute | Τι ορίζει |
| --- | --- |
| Domain | Σε ποια domains στέλνεται. Αν λείπει, στέλνεται μόνο στο ακριβές host που το έβαλε. Αν οριστεί (π.χ. `Domain=example.com`), στέλνεται και σε όλα τα subdomains |
| Path | Για ποια paths του site στέλνεται (π.χ. `/` για όλο το site) |
| Expires / Max-Age | Πότε λήγει |
| Secure | Στέλνεται μόνο μέσω HTTPS |
| HttpOnly | Δεν διαβάζεται από JavaScript |
| SameSite | Αν στέλνεται όταν το request προέρχεται από άλλο site |

### Διάρκεια: session και persistent cookies

- **Session cookie:** δεν έχει `Expires` ή `Max-Age`. Σβήνεται όταν κλείσει ο browser (ή η συνεδρία του). Χρησιμοποιείται κυρίως για login.
- **Persistent cookie:** έχει ημερομηνία λήξης και μένει αποθηκευμένο μέχρι τότε, ακόμα κι αν κλείσεις τον browser. Χρησιμοποιείται για «Remember me», γλώσσα, προτιμήσεις.

### First-party και third-party cookies

Η διάκριση δεν έχει να κάνει με το ποιος έγραψε το cookie, αλλά με το ποιο site βλέπεις εκείνη τη στιγμή σε σχέση με το domain του cookie.

Το site που βλέπεις είναι αυτό που φαίνεται στη γραμμή διεύθυνσης. Μια σελίδα όμως φορτώνει συχνά πόρους από άλλα domains: εικόνες, scripts, διαφημίσεις, βίντεο, κουμπιά «Like». Κάθε ένας από αυτούς τους πόρους είναι ένα ξεχωριστό request, και η απάντησή του μπορεί να περιέχει `Set-Cookie`.

- **First-party cookie:** ανήκει στο ίδιο site που βλέπεις. Επισκέπτεσαι `shop.example.com` και ο server του `shop.example.com` βάζει cookie. Χρησιμοποιείται για login, καλάθι αγορών, γλώσσα.
- **Third-party cookie:** ανήκει σε διαφορετικό site από αυτό που βλέπεις. Επισκέπτεσαι `shop.example.com`, και η σελίδα φορτώνει μια διαφήμιση από `ads.tracker.com`. Η απάντηση του `ads.tracker.com` βάζει cookie. Για τον browser, το cookie ανήκει στο `tracker.com`, όχι στο `example.com`.

```text
Βλέπεις: https://shop.example.com
│
├── φορτώνει /style.css         (example.com)  → first-party
└── φορτώνει ads.tracker.com    (tracker.com)  → third-party
```

Για να τα ξεχωρίζεις: συγκρίνεις το domain του cookie με το domain της γραμμής διεύθυνσης. Ίδιο site σημαίνει first-party, διαφορετικό σημαίνει third-party.

### Γιατί υπάρχουν τα third-party cookies

Έχουν και νόμιμες χρήσεις: embedded υπηρεσίες (χάρτες, βίντεο, συστήματα πληρωμής μέσα σε iframe), single sign-on, widgets chat. Η κύρια χρήση τους όμως είναι η παρακολούθηση (tracking) και η διαφήμιση.

### Πώς γίνεται το tracking

1. Επισκέπτεσαι το site Α, που φορτώνει script από `tracker.com`. Ο `tracker.com` σου βάζει cookie με μοναδικό ID, π.χ. `uid=777`.
2. Επισκέπτεσαι το site Β, που φορτώνει κι αυτό από `tracker.com`. Ο browser στέλνει πάλι `uid=777` στον `tracker.com`, μαζί με τη σελίδα από την οποία έρχεται (header `Referer`).
3. Ο `tracker.com` ξέρει πια ότι το ίδιο ID επισκέφθηκε τα Α και Β, και χτίζει προφίλ με όλα τα sites που βλέπεις.

Τα sites Α και Β δεν χρειάζεται να συνεργάζονται μεταξύ τους. Αρκεί που και τα δύο φορτώνουν τον ίδιο τρίτο.

### Τι κάνουν οι browsers σήμερα

Λόγω ιδιωτικότητας, οι browsers περιορίζουν τα third-party cookies, αλλά **όχι όλοι με τον ίδιο τρόπο**. Safari και Firefox τα μπλοκάρουν ή τα περιορίζουν από προεπιλογή, ενώ η στάση του Chrome έχει αλλάξει επανειλημμένα και αφήνει επιλογές στον χρήστη. Γι' αυτό δεν μπορείς να βασίζεσαι ότι ένα third-party cookie θα δουλέψει, ούτε ότι θα είναι μπλοκαρισμένο. Για τον έλεγχο της συμπεριφοράς στον δικό σου browser, δες τις ρυθμίσεις απορρήτου του.

Το attribute `SameSite` είναι ο μηχανισμός που καθορίζει αν ένα cookie στέλνεται σε cross-site requests.

### Άλλοι τρόποι αποθήκευσης στον browser

Τα cookies δεν είναι ο μόνος χώρος αποθήκευσης. Η διαφορά που μετράει:

| | Cookies | localStorage / sessionStorage |
| --- | --- | --- |
| Στέλνονται αυτόματα στον server | Ναι, σε κάθε request | Όχι |
| Διαβάζονται από JavaScript | Ναι, εκτός αν είναι HttpOnly | Πάντα |
| Μέγεθος | ~4 KB ανά cookie | Αρκετά MB |

Τα δεδομένα στο localStorage δεν φεύγουν μόνα τους προς τον server, αλλά είναι πάντα προσβάσιμα σε οποιοδήποτε script της σελίδας, άρα και σε ένα script που μπήκε μέσω XSS. Για αυτό ένα session ID σε HttpOnly cookie θεωρείται ασφαλέστερο από το ίδιο σε localStorage.

### Σύνδεση με την ασφάλεια

- **Το cookie συνήθως είναι η ταυτότητά σου.** Όποιος αποκτήσει το session cookie, μπορεί να παρουσιαστεί ως εσύ (Session Hijacking, Κεφάλαιο 6).
- **Ο browser τα στέλνει αυτόματα**, ακόμα κι όταν το request ξεκινάει από άλλη σελίδα. Αυτό επιτρέπει το CSRF.
- **Ο χρήστης μπορεί να αλλάξει τα cookies του από τα DevTools.** Άρα ο server δεν πρέπει ποτέ να εμπιστεύεται τιμή cookie που φαίνεται «δική του» (π.χ. `role=user`, `price=10`). Η πληροφορία πρέπει να ελέγχεται ή να βρίσκεται στον server, με το cookie να κρατάει μόνο ένα τυχαίο ID.
- **Τα third-party cookies επηρεάζουν την ιδιωτικότητα** (tracking) και συνδέονται με το GDPR, γι' αυτό τα sites ζητούν συγκατάθεση για cookies.

## 2.8 Τι είναι το DNS;

Όταν γράφεις `www.google.com` στον browser, πώς γνωρίζει ο υπολογιστής σου ποιον server να βρει; Εδώ μπαίνει το **DNS** (Domain Name System).

> **DNS:** Ο «τηλεφωνικός κατάλογος» του Internet. Μετατρέπει ονόματα domains (π.χ. `google.com`) σε IP διευθύνσεις (π.χ. `142.250.185.14`) που καταλαβαίνουν τα δίκτυα.

Η διαδικασία είναι:

1. Γράφεις `www.google.com` στον browser.
2. Ο browser ρωτάει τον DNS server: «Ποια IP έχει το google.com;»
3. Ο DNS server απαντάει με την IP διεύθυνση.
4. Ο browser συνδέεται στον server με αυτή την IP.

## Σύνοψη

- Το Internet λειτουργεί με μοντέλο client-server: ο client κάνει αιτήματα, ο server απαντάει.
- Το HTTP είναι το πρωτόκολλο επικοινωνίας. Το HTTPS είναι η κρυπτογραφημένη έκδοσή του.
- Τα HTTP requests έχουν μεθόδους (GET, POST κ.λπ.) και τα responses έχουν status codes.
- Τα cookies αποθηκεύουν πληροφορίες σύνδεσης στον browser.
- Το DNS μετατρέπει domain names σε IP διευθύνσεις.
